# 隐私与数据流说明

本文面向部署者和数据控制者，说明本工程会保存什么、什么时候可能访问网络、哪些边界由代码强制、哪些风险必须由使用者自行承担。安全行为以代码为最终依据；若本文与实现冲突，应先停用并修正代码，而不是依赖本文的承诺。

> 本通用交付只包含合成测试和离线验证。准备、导入、规划和本地检索不调用大模型；仓库测试不访问网络。只有使用者显式下载公开模型、安装依赖，或为经授权的蒸馏/聊天配置了外部服务时，才可能发生外部网络请求。本次交付没有执行真实语料的全量蒸馏。

---

## 1. 数据分级

真实聊天数据必须写入项目源码树之外的私有 `CHAT_DATA_DIR`。不要把真实 `data/`、`prepared/`、`reports/`、人物产物或凭据放进 Git 仓库。未设置 `CHAT_DATA_DIR` 时程序会回退到项目根，该回退仅用于合成测试/演示，禁止承载真实聊天。下表路径均相对于这个私有数据根。

| 位置 | 内容 | 敏感级别 |
| --- | --- | --- |
| 原始导出文件（用户自行保管） | 完整聊天原文、发送者、时间 | 最高 |
| `prepared/` | 规范化消息、来源账本、审计、异常/重复记录 | 最高 |
| `data/real_history.sqlite` | 真实消息、来源、索引元数据 | 最高 |
| `data/ai_sessions.sqlite` 等 AI 会话库 | 用户对 AI 的提问、AI 回复、引用快照 | 高 |
| `mirror_directory`（默认 `exes/<owner>/<slug>/`） | 人物运行镜像、SKILL、claim、timeline、Chroma、AI 标注；实际位置以 `runtime/installation.json` 为准 | 高 |
| `artifacts/` | 计划、训练分段、checkpoint、蒸馏产物 | 高（checkpoint 可能含模型原始回复） |
| `data/models/` 与 `reports/embedding-model-manifest.json` | 公开模型权重和完整性 manifest | 中 |
| `config/provider.json` | 服务名、URL、模型、价格；不含密钥 | 中 |
| `config/provider.env` | `CHAT_LLM_API_KEY` | 最高（凭据） |
| `config/privacy-consent.json` | 授权范围、来源/计划哈希、指纹、预算 | 高 |
| `config/local-login.json` | 本机 UI 用户名与随机密码（0600） | 最高（凭据） |
| `logs/`，`runtime/` | 运行日志、PID、安装状态、无正文的用量账本 | 中高 |
| `backups/` | 上述数据的打包副本 | 最高 |

向量不是匿名化。真实历史 embedding 仍可能携带语义、人物关系和时间信息；不能因为“只是向量”就降低保护级别。派生 claim、时间线、人物 SKILL 也仍然是敏感画像。

## 2. 本地处理流程与网络边界

### 2.1 准备（无模型、无网络）

`scripts/chat_memory_tool.py prepare` 在本地解析逐行文本，生成来源 SHA-256、行号、发送者、角色 A/B 和文本。它不会联网，也不会调用模型。

准备结果可能包含未脱敏的原文。程序不会自动识别所有姓名、电话、住址、账号、验证码或第三方隐私。部署者必须在导出/准备前完成人工审查，并只处理自己有权处理的记录。

### 2.2 导入与检索（无模型、无外部网络）

`import_history.py` 使用固定版本、本地文件加载的 BGE embedding，将消息写入 SQLite/Chroma，并写本地安装状态。适配层强制：

- `HF_HUB_OFFLINE=1`、`TRANSFORMERS_OFFLINE=1`；
- `EX_MEMORY_LOAD_DOTENV=false`、`EX_MEMORY_USE_KEYCHAIN=false`；
- 上游数据库与日志目录重定向到本项目数据根；
- embedder identity（模型、revision、权重哈希）必须在向量写入前校验。

普通 `memory_search` 与 Web/MCP 检索只读取本地索引，`llm_calls=0`。不过，操作系统、文件系统、备份软件和本地恶意软件不在本工程的保护范围内。

### 2.3 规划（无模型、无网络）

`python -m distillation.pipeline plan` 只在本地切分会话、隔离 holdout、计算 token 上界和费用上界，并写入 `plan.json`。holdout 不进入训练调用。

### 2.4 蒸馏（仅显式授权后才可能联网）

蒸馏流水线不会自动创建客户端。只有以下条件全部满足时才允许请求：

1. `config/provider.json` 有合法服务、HTTPS（或本机回环 HTTP）、模型和上下文预算；
2. `config/provider.env` 或进程环境提供项目专用的 `CHAT_LLM_API_KEY`（本机无密钥端点除外）。回环地址只说明请求先到本机网关，不证明模型在本机运行；网关可能把内容转发给下游服务。使用者必须自行确认该路由的数据去向，再填写授权；
3. `config/privacy-consent.json` 存在用途为 `distill_trial` 或 `distill_full` 的有效授权；
4. 授权绑定当前 **provider 指纹、已导入来源 SHA、计划哈希、调用次数和费用/路由模式**；
5. 请求由唯一出口 `adapters/privacy.py` 创建。

发送给所配置模型端点的蒸馏内容通常包括：

- 系统指令（证据约束、角色说明、输出 JSON schema）；
- 所选训练段的紧凑消息行：`source_line`、时间、`sender=A/B`、消息正文、会话 id；
- 合并阶段的 claim 视图和摘要输入，而不是原始完整聊天库。

不会发送：

- holdout 分段；
- 未选中的其他训练段；
- 完整 SQLite、完整向量库或任意文件系统路径；
- provider 密钥明文（密钥只通过服务的认证头传递，不写入日志/产物）；
- 本机登录密码；
- 其他 slug/owner 的运行目录。

但模型服务会看到被选中的聊天原文、时间、发送者角色和上下文。**这是有意为之的必要数据暴露**；是否允许、服务如何保留/训练/跨境传输，由部署者与服务商条款决定。适配层禁用自动重试和供应商切换，以减少重复外发；同一节点永久最多两次尝试，失败会以 `incomplete` 明确记录。

### 2.5 Web 聊天与 MCP 模拟聊天（需额外授权）

- Web `/chat/api/<slug>/search` 只检索；`/chat` 需要 `chat` 授权。
- Web 和 MCP 的聊天会把用户消息、必要的会话历史、真实历史检索证据和蒸馏人物信息发送给配置的模型服务。
- 回复正文不带可见模拟/AI 标签；独立存储元数据保留 `origin=ai_simulation`。
- AI 会话、AI 向量和真实历史库分开存储；AI 内容不能作为真实历史的事实来源。
- MCP `simulate_persona` 必须先满足 `DSH_MCP_CHAT_AUTH=true` 和 `chat` 授权；任一缺失都不会发送或创建会话。
- 用量账本 `runtime/api-usage.json` 只记录调用计数/费用/用途等元数据，不保存聊天正文。

### 2.6 外部网络请求清单

| 触发者 | 目标 | 说明 |
| --- | --- | --- |
| 部署者运行 `setup.sh` | Python 包索引 | 安装锁定依赖 |
| 部署者显式运行模型下载器 | `huggingface.co` 公开固定 revision | 只下载固定 BGE 文件和配置，不使用匿名 token |
| 经授权的蒸馏 | `provider.json` 中用户配置的服务 | 发送所选训练段聊天与蒸馏指令 |
| 经授权的 Web/MCP 聊天 | 同上 | 发送用户输入、会话和检索证据 |

除此之外，代码不发送遥测、不访问更新服务器、不在后台抓取聊天、不自动上传日志。上游 Chroma/OpenTelemetry 相关 telemetry 变量在进程内被关闭。

## 3. 授权与最小权限

授权文件只保存：

- 用途（试跑、全量、聊天）；
- provider 指纹、允许的服务名/URL/模型；
- 来源 SHA-256、计划哈希；
- 最大调用次数、固定费用上限，或 usage-only 路由确认；
- 用户确认标记和授权的 grant id。

授权不保存 API 密钥。`provider` 的任何绑定字段改变，或真实历史来源 SHA/计划改变，旧授权都不再匹配。`configure.py` 不读取密钥、不创建客户端、不发起请求；它只把一次明确确认写成授权记录。

有效的使用原则：

- 先离线规划，再核对调用次数和费用上界；
- 试跑使用 `distill_trial`，全量使用 `distill_full`，聊天使用 `chat`；
- 不给全量授权一个低于计划上界的预算；
- 不用 usage-only 伪装固定费用；
- 不在未核对第三方数据政策时开启聊天/全量。

## 4. 防止误外发和路径越界的代码措施

- **唯一出口**：只有 `adapters/privacy.py` 的授权客户端可以创建模型请求；适配器不允许任意 SDK 参数、流式、自动重试或备用端点。
- **URL 基本校验**：拒绝 URL 内嵌凭据、query、fragment；非 loopback 必须 HTTPS。此校验不等同于完整 SSRF 防护；不要在本机运行不可信服务。
- **固定数据根**：`CHAT_DATA_DIR` 决定 SQLite、模型、授权和镜像位置；上游导入/认证目录被重定向，不会写回 vendored 源码树。
- **来源一致性**：prepare 计算 SHA，import 检查 audit SHA 与源文件；授权检查真实历史来源 SHA；计划检查消息文件 SHA。
- **失败关闭**：未授权、来源/计划不匹配、persona 不完整、MCP 开关关闭、授权指纹变化，都拒绝请求而不是降级或改用其他服务。
- **权限**：运行目录 0700；配置、产物、manifest 与本地登录文件 0600；原子替换减少半写状态。
- **字段白名单**：MCP/检索只返回 canonical 验证过的来源、发件人、时间、有界引用和有限元数据；不返回完整路径、prompt、密钥、任意 SQL。
- **日志最小化**：固定事件名和计数，不拼接聊天正文、路径、异常原文；MCP stderr 只输出固定事件。
- **AI 隔离**：真实历史 origin 只能来自本地导入；AI 摘要和会话不得回写真实历史。

这些措施不能防止：

- 拥有本机账户、数据目录或备份访问权的攻击者；
- 恶意/被篡改的依赖、模型文件或 MCP 客户端；
- 提供商的记录、训练、滥用或法律强制；
- 用户把原文、密码或密钥粘贴到第三方聊天/工单；
- 磁盘、快照、同步盘和备份的残留副本；
- 聊天记录中的 prompt injection 等社会工程风险。

## 5. 日志、checkpoint 与备份风险

- `logs/` 可能含启动错误、堆栈、文件路径，不应公开。
- 蒸馏 checkpoint 为支持断点续跑可能保存模型响应、usage、模型标识和校验信息；其中可能包含聊天引文。它们位于 `artifacts/`，必须按高敏感数据保护。
- `runtime/api-usage.json` 只用于调用计数/费用门禁；它是账本不是内容日志，但仍是内部状态。
- 备份包含 `config`、`data`、`prepared`、`reports`、`artifacts`、`runtime`，以及安装记录中实际的 `mirror_directory`/独立 `persona_directory` 时，等同于复制了完整敏感画像、密码和授权，必须加密并限制访问。`scripts/manage_data.py` 会校验这些安装路径都位于 DATA_ROOT 内，并把自定义镜像纳入归档；备份文件仍是普通文件，不是安全擦除或访问控制的替代品。
- 普通文件删除不等于安全擦除。SSD、快照、系统日志、云同步和外部备份可能保留副本；合规擦除应使用平台能力并在项目外评估。
- 恢复旧备份可能恢复过期授权、旧 provider 指纹或旧来源 SHA。恢复后必须重新校验；不要绕过失败关闭去“修复”授权。

## 6. 使用者责任

部署者应至少：

1. 获得对话参与者对导出、处理、蒸馏和模拟的合法授权；
2. 遵守当地法律、劳动合同、保密义务和聊天服务条款；
3. 只处理必要的最少数据，先人工删除无关第三方隐私；
4. 将 `CHAT_DATA_DIR`、密钥、备份和登录文件限制在本机最小权限账户；
5. 在配置任何外部服务前阅读其数据保留、训练、跨境和滥用政策；
6. 不把模拟回复冒充真人陈述，不用于欺骗、骚扰、画像滥用或高风险决策；
7. 在分享问题、日志或截图前再次脱敏；
8. 不再需要时按备份/删除流程清理所有副本，并自行完成安全擦除评估。

本项目不收集遥测，也不代表任何聊天平台或模型供应商。使用者是数据控制者，必须自行判断处理行为的合法性与适当性。
